# Project 1 — Starter Package (D2L)

Download this folder and work locally. Submit **only** `solution.py` on D2L.

## Folder contents

| File | Purpose |
|------|---------|
| `specs.md` | Full project specification |
| `solution.py` | Your implementation file — complete the stubs and the engineering sign-off |
| `tests.py` | Unit tests for local verification and validation |
| `imgs/` | Diagrams referenced in `specs.md` |

## Quick start

1. Type your name after `Engineer Name:` in the Engineering Verification and Validation Sign-Off at the top of `solution.py`.
2. Implement the methods marked `INSERT DOCSTRING HERE` or `pass`.
3. Run tests:

```bash
python3 -m unittest tests.py -v
```

4. Complete the sign-off and upload **only** `solution.py` on D2L.

## Tests

A full local pass reports the tests listed in `specs.md`.

Passing the supplied tests is evidence, but not proof, of correctness. Understanding is assessed separately through the Project Validation Quiz and ARCs.

## Note on naming

During course development the stub file is called `starter.py`. The shipped student package uses `solution.py` because that is the only file you upload.
